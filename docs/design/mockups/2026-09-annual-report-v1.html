年報 — 一年の参拝をふりかえる

v1・動きの試作 v1 とも 2026-09-26 オーナー確認（方向はこれで）

関連: docs/design/2026-09-annual-report-spec.md（同じ内容の Markdown）/ direction.md Phase 1「パーソナル年報」/ 収益化の設計 §4 / feature-list P1-04。画面は動きの前の静止画で、中の数字は例。写真の枠には実物の御朱印の写真が入る。

0. 決めたこと 2026-09-26 オーナーと

  1. アプリ紹介動画のような、動きのあるふりかえり。数字を並べる画面ではなく、シーンが動いて流れていく
  2. 自動で流れる。押しても操作できる: 押している間は止まり、画面の左を押すと前、右を押すと次のシーンへ（Instagram のストーリーに近い）
  3. 12月から、その年の分が見られる。過ぎた年はいつでも（年末の行事にする）
  4. 共有は、まとめの画像1枚 → v1 では共有しない（2026-09-27 に見直し）
  5. 音はなし。動きだけで動画らしさを出す
  6. お知らせは出さない（アプリの中の案内・バナーも、通知も）
  7. 12月に初めてアプリを開いたとき、1回だけ自動で再生する。あとはあゆみから見る
  8. 1月からは、あゆみの下の方へ移す（12月の間だけ、あゆみのいちばん上）
  9. トーンは明るい案（和紙と朱）（2026-09-27）
  10. 画面に出す呼び方は「{年}年のふりかえり」（2026-09-27）
  11. v1 では共有しない（2026-09-27）。共有の画像を試作したが、数字と地図の並びでは人に見せる理由が弱かった（2026-09-annual-report-share-v1.html は不採用）。締めは「もう一度見る」「閉じる」だけ

1. 何をするか

  • その年に記録した御朱印から、あなたの一年の参拝を 30〜45秒の動くふりかえりにして見せる
  • 見るのは本人だけ。SNS の機能は持たない。外へ出すのは、本人が選んだときのまとめの画像1枚だけ
  • 新しく入力してもらうものは無い。使うのは、参拝した日・寺社（名前・神社かお寺か・都道府県・位置）・御朱印の写真・バッジ・巡礼の進み具合
  • 「その年」は日本時間の 1月1日〜12月31日の参拝した日で数える

2. シーン 叩き台・1シーン 4〜6秒・赤い字は動き

3. 入口と時期

時期自動で再生あゆみの入口
1月〜11月しない過ぎた年の年報だけ、あゆみの下の方の「年報」の欄（2026年はまだ無い）
12月（日本時間の1日〜31日）12月に初めてアプリを開いたとき、1回だけ。✕ で閉じたら、あとはあゆみからあゆみのいちばん上に「2026年のふりかえり」のカード
翌年の1月からしない「2026年のふりかえり」は、あゆみの下の方の「年報」の欄へ移る。いつでも見られる
12月に初めて開いたとき: メインのタブの画面が出たところで、年報がそのまま流れ始める（1回だけ）。
オンボーディング・ログイン・記録の途中では出さず、次にメインのタブが出たときに出す。ログインしている人だけ。途中で ✕ を押しても、もう自動では出さない（その年・そのアカウントごとに端末に覚えておく）。
12月のあゆみ: いちばん上に「2026年のふりかえり」。押すと再生。その年の記録が0件なら、自動再生もカードも無し。
1月からのあゆみ: 「2026年のふりかえり」は下の方の「年報」の欄へ。過ぎた年はいつでも見られる（年が増えたら並ぶ）。
  • 気づいてもらう入口は「12月に1回だけの自動再生」と「あゆみのカード」だけ。アプリの中のお知らせも、通知も出さない
  • 12月より前に確かめる手段: 設定の「開発用」に「年報を見る」「12月として自動再生を試す」（開発用のアプリだけ）
  • App Store の審査（11月）には見えないので、審査のメモに「12月1日から自動で流れ、あゆみにも入口が出る」と書く（Guideline 2.3.1 の「隠れた機能」と見なされないように）
  • 12月かどうかはアプリの中で日本時間の日付を見る。12月1日に作業は要らない。JS だけなので、ストア用ビルドでも OTA でも届けられる

操作

操作: 自動で次のシーンへ。押している間は止まる。左の3分の1で前のシーンの頭へ、右で次へ。✕ でいつでも閉じる（開き直すと最初から）。最後のシーン（締め）で止まる。
視差効果を減らす: 動きを止め、各シーンの最後の形をすぐ出す。自動では進まず、押して進める

4. 記録が少ない人 例: その年に2枚

データが足りないシーンは飛ばす（§2 の「足りないとき」）。2枚なら 表紙 → 数字 → 地図 → 締め の4シーン・約20秒。寂しくならないかは試作で見る。

5. 色とトーン 試作で決める

明るい案（和紙と朱）に決定（2026-09-27）。下は比べたときの暗い案（夜の境内・使わない）。

6. 無料とプラス 収益化の設計 §4

無料プラス
その年の年報を見る過ぎた年の年報すべて・印刷向けの書き出し（将来）
  • 課金をオンにするまでは、全部を誰でも使える。コードには「プラスなら」の分かれ目だけ作る（#270 と同じ）
  • 2026年は最初の年なので、プラスの差が出るのは 2027年から

7. 作りのメモ 契約書で決める

  • 動きは今と同じ RN の Animated と react-native-svg（あゆみの地図・保存直後の動きと同じ素材）。Reanimated・Skia・Lottie は足さない方針
  • 共有をやめたので、新しいネイティブの部品は要らない（JS だけ）。10/1 以降のビルド（ビルド 20 以降）を入れた人には OTA でも届けられる
  • 集計は、その年の記録を1回取ってアプリの中で数える（サーバーの変更は要らない見込み）

8. 試作で決めること

  1. シーンの順番と中身（§2 から足す・削る）
  2. 色とトーン → 明るい案
  3. 御朱印の写真の使い方: コラージュは試作どおり（共有は作らない）
  4. 記録が少ない人（1〜2枚）が寂しくならないか（§4）
  5. 呼び方 →「{年}年のふりかえり」

9. やらないこと（v1）

  • 共有（画像の書き出し・共有シート）・動画の書き出し・音
  • 他人の年報を見る・比べる・ランキング
  • 通知・アプリの中のお知らせで知らせる（気づいてもらうのは、12月に1回だけの自動再生とあゆみのカード）
  • 年の途中の「今年ここまで」（12月より前には出さない）
  • 印刷向けの書き出し（プラスの候補として将来）
