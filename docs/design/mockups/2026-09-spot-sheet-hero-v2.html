スポットのシートの顔 — 試作 v2（案B を作り込んだ版）

地図のピンのシートの上に出す「場所の顔」です。半分のときは 80pt の細い帯、大きく開くと 208pt。並びと言葉は今のシートのままで、足したのは顔だけです。
いちばん見てほしいのは、写真の無い寺社（5・6）の帯が、写真のある寺社（3・4）と並べて見劣りしないか。写真の無い帯は2案あり、上の「写真の無い帯」で切り替えます。ページの下の「並べて見る」は、写真のある寺社と写真の無い寺社（案い・案ろ）を3台並べています。
シートはつまみ・帯を押すか、上下にドラッグして開閉します（帯もドラッグについて伸びます）。5・6 で「記録する」を押すと、記録した瞬間の動きになります。写真の帯の名前の上の「写真: …」を押すと、撮影者の吹き出しが出ます。

素材: 色・余白・文字 = src/theme／シートの中身 = spot-detail の各コンポーネントの StyleSheet／和紙 = GoshuinArt.tsx の地と筋・ImageLoadingCover.tsx の内枠／布表紙・題箋の紙・綴じ目の陰・表紙の影 = LoadingBook.tsx（#275）の色／自分の御朱印 = GoshuinArt.tsx（見本の御朱印。本物の記録は使っていません）／印 = Seal.tsx の SEAL_FRAMES と、v1 で彫った鳥居・お堂／捺す動き = ManganSeal.tsx／地図 = assets/map-style.json + assets/map-pins／ 写真 = Wikimedia Commons: 八坂神社 西楼門（DXR, CC BY-SA 4.0）・鹿苑寺（Basile Morin, CC BY-SA 4.0）・厳島神社（Jakub Hałun, CC BY-SA 4.0）。帯に合わせてトリミングしています

写真の無い帯

写真の無い帯（2案）

  • 案い「空押し」 — 和紙に、その寺社の印（神社は鳥居・お寺はお堂）を帯いっぱいの大きさで、色を付けずに型だけ押す。小さな印を真ん中に置くと「画像がありません」の顔になるので、印は帯からはみ出す大きさにした。半分のときは鳥居の笠木・お堂の屋根が帯を横切るので、細い帯でも何の寺社かが絵で分かる。記録すると、その印に朱が乗り（0.5秒）、朱はうすい跡になって残り、右に自分の御朱印のページが出る（0.25秒）。
  • 案ろ「閉じた御朱印帳」 — 帯を、#275 の読み込み中の本と同じ朱の布表紙にして、右に縦長の題箋（紙の札）、札の上にまだの印。行っていない寺社は閉じた帳面、行った寺社は開いた帳面、という分け方。記録すると、題箋に朱が捺され（0.5秒）、表紙が左の綴じ目を軸に手前へ開いて、中のページが出る（0.25秒）。表紙は行っていない寺社だけで、行った寺社（1）は開いた頁になる。
  • 比べると: 案いは静かで、写真の帯の隣では色が弱い（形で持たせる）。案ろは色の重さが写真に負けないが、半分のとき朱の帯がボタンの橙と近い。

行った寺社

  • 写真なし — 前の版の「右にページ」のまま。ページを大きくし、半分のときはページの下がシートの白に隠れて、頁に挟まっているように見せる。回数ぶん後ろに重なる（束）。案いは捺した印の朱の跡（帯いっぱい・うすく）の上にページ。帯が寂しくならず、行っていない寺社との違いが色で分かる。案ろは開いた頁（左に綴じ目の陰・内枠）にページ。
  • 写真あり — 写真はそのまま。右下に自分の御朱印のページが一枚挟まる（下の端がシートに入り込む）。半分では右上の小さな束、開くと名前の上まで降りてくる。下の端は、札（神社・訪問済み）の下で白にとけて入る。

撮影者の表示

  • 帯の左下、名前のすぐ上に「写真: 撮影者 / ライセンス」（11pt・白字に薄い墨の地）。上の角はつまみ・御朱印のページと重なるので避けた。名前と一緒に動くので、半分でも大きくでも名前の上にいる。
  • 押すと吹き出し。撮影者・ライセンス（リンク）・Wikimedia Commons の元の写真（リンク）・「帯に合わせてトリミングしています」。いつも上に出す（半分のときは地図の側、大きく開いたときは帯の写真の上）。ほかの所を押すかドラッグすると閉じる（0.2秒）。

動き（実装の注記）

  • 帯の高さは動かさない。帯は 208pt のまま描き、名前から下の中身を translateY で最大 128pt 持ち上げて帯の下に重ねる。写真の位置、印・ページ・題箋の位置と大きさも translateY・translateX・scale だけで決める。
  • どれもシートの translateY を interpolate した値（inputRange は [expandedPosition, compactPosition]、両側 clamp）。footerTranslateY と同じく compactPosition で useMemo し直す。native driver のまま、ドラッグにも spring にもついてくる。この試作も、シートの y ひとつから全部を計算している。
  • 半分の高さの実測（handlePrimaryLayout）は、帯を 208 で測るので 128 を引く。
  • 写真は resizeMode="cover" を使わない。幅 390 と写真の縦横比から高さを出し、focus_y（見せたい所の縦の位置 0〜1）を、名前にかからない所の真ん中に来るように translateY を決める。半分と大きくの2点で clamp して interpolate する（端が帯からはみ出さない）。そのため写真のデータに width・height・focus_y を持つ。

実装で怪しい所

  • 帯を 208 で描いておくので、半分のときも帯の見えない所（128pt）を描いている。中身の下には、持ち上げた分の白い余白を足す（無いと帯が透ける。この試作で一度起きた）。
  • 案いの印は Seal と同じ 100×100 の図形を 250〜300pt に広げる。線もそのまま太るので、印の彫りの粗さ（手彫りの揺れ）が大きく見える。実機の 3 倍の画面で一度見たい。
  • 中身を持ち上げると、中身の下の 128pt が空く。開いた状態の ScrollView の下の余白（paddingBottom）と合わせて確かめる。
  • 写真の縦横比が横長すぎる（高さが 208 に足りない）写真は、focus_y だけでは埋まらない。そのときは拡大の係数も持つ。
  • 案ろの表紙が開く動き（perspective + rotateY）は、iOS の裏面の扱いに注意（#275 の「ちょうど 180° にしない」と同じ罠）。100° で止めて、裏は描かない。手前に起き上がる途中は帯の overflow: hidden で切れる。
  • 記録の動きの間は、印・ページ・表紙の opacity・scale・rotateY だけを動かす。帯の開き（.rect の transform）とは別のビューに分けておかないと、同じ transform を取り合う（この試作でも一度ぶつかった）。
  • 吹き出しはシートの overflow: hidden の外に置く（シートの兄弟）。位置はシートの translateY から出す。
