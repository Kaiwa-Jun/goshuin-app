# 要件: 月参り・満願とバッジの軸（UX メモ 提案④③）

デザイン: **`docs/design/mockups/2026-09-tsukimairi-v2-motion.html`**（動きまで触れる試作）
出典: UX メモ https://claude.ai/artifact/HdRsemF7phLZVYPG1CjNu6
ステータス: **確定（2026-09-21 ユーザー承認）。実装可**

## 1. なぜ、これだけ「連続」を入れていいか

**月参りは、アプリが発明した仕組みではなく、もとからある作法**。同じ神社に毎月1回参拝し、
12ヶ月続けると「満願」となって、神社が特別な御朱印をくれることがある。

| 論点       | Duolingo のストリーク | 月参り                 |
| ---------- | --------------------- | ---------------------- |
| 周期       | 毎日                  | **月に1回**            |
| 対象       | アプリ全体で1本       | **神社ごと**           |
| ご褒美     | アプリが発明した      | **神社が実際にくれる** |
| 決めたのは | アプリ（囲い込み）    | **その文化**           |

**アプリの仕事は、作り出すことではなく気づくこと。** だから「月参りをする」と宣言させない。
参拝の記録から勝手に気づいて、出すだけ。

## 2. 数え方

- **月参りの月数** = その寺社について、**連続する暦月に1件以上の `stamps` がある**月の数
- 同じ月に何枚記録しても **1ヶ月**
- **12ヶ月で満願**。満願のあとも数え続ける（13ヶ月目、14ヶ月目…）

### 2-1. 「途切れた」の判定 — 今月は猶予

**前の月に来ていなければ途切れ。今月はまだ数えない。**

| いま     | 最後の参拝 | 判定                                       |
| -------- | ---------- | ------------------------------------------ |
| 10月15日 | 9月        | **続いている**（10月はまだ終わっていない） |
| 11月1日  | 9月        | **途切れた**（10月に来ていない）           |

月が変わった瞬間に消えると「まだ月半ばなのに」になる。猶予を2ヶ月にすると、実際には
途切れているのに残り続ける。

⚠️ **`visited_at` は DATE 型。`new Date()` を挟まない**（Issue #204 と同じ1日ずれを踏む）。
`YYYY-MM` を文字列として切り出して数える。**月境で数えるので、#204 はこの機能の前提条件だった。**

## 3. どこに、いつ出すか

| 場所           | 続いている（2ヶ月以上） | 途切れている                                     |
| -------------- | ----------------------- | ------------------------------------------------ |
| **あゆみ**     | 「月参り」の一覧に出す  | **出さない**                                     |
| **寺社の詳細** | 月参りカード            | カードは出さず、御朱印一覧の上に**1行**だけ      |
| 再開したら     | —                       | 次に記録したら1ヶ月目。**2ヶ月目でカードが戻る** |

- **1ヶ月ではカードを出さない。** 1回来ただけの人に「月参り」を名乗らせない
- **途切れたらカードは役目を終える。** カードの仕事は「満願まであと◯ヶ月」を見失わせないこと
- 途切れた寺社の1行は「**月参り ・ 最長 7ヶ月**」。責める文言はどこにも出さない
- **あゆみに一覧を置くのが要**。寺社の詳細にしか無いと、その寺社を自分から開いた人しか
  気づけない ──「気づくこと」という目的を果たせない

## 4. 見た目

### 4-1. 月参りカード（寺社の詳細）

| 要素       | 仕様                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 置き場所   | `SpotSheetActions` の下、御朱印グリッドの上                              |
| カード     | 白・角丸16・**上辺に3pxの朱 `#DC2626`**                                  |
| 見出し     | 「月参り」16px/700 + 右に朱のチップ「7ヶ月目」                           |
| 説明       | 「毎月この神社へ。12ヶ月で満願です」12px `#4B5563`                       |
| 丸         | 12個を横一列。達成 `#DC2626` / 次の1つ `#9CA3AF` の破線 / 残り `#E3E4E8` |
| 両端       | 左に開始月「3月」、右に「満願」10px `#9CA3AF`                            |
| 結び       | 「満願まで、**あと5ヶ月**。」（朱の太字）                                |
| 満願のとき | 12個すべて朱。結びは「**満願**」。13ヶ月目からは「満願 ・ 2周目 3ヶ月」  |

### 4-2. あゆみの「月参り」一覧

地図・最近の参拝の下、獲得バッジの上。1行 = 1寺社。

`寺社名（104px）｜ 12個の小さい丸 ｜ あと5`

次の月の丸は**破線で開いたまま**置く。「今月まだです」とは書かない。**それが煽らずに気づかせる形**。

### 4-3. 満願の瞬間 — 保存直後の続き

独立した画面は作らない。12ヶ月目を記録した直後の画面で、

1. いま授かった**御朱印の写真の上に、満願の朱印が上から押される**（0.5秒）
2. 12個の丸がすべて朱で出る
3. 「湯島天満宮 ・ 満願」「12ヶ月、毎月おまいりしました」
4. **「満願の御朱印をいただけることがあります。社務所で尋ねてみてください」**

4は必ず出す。**ご褒美はアプリの外にある**ことを画面の文言として持つ。バッジが賞品にならないように。

### 4-4. 同時に取れたバッジ

**文章の行を増やさず、横に並べる。** 3つでも4つでも高さが変わらない。
46px の円 + 10px のラベル、1つずつ 0.15秒ずらしてポンと出す。

⚠️ **満願は、御朱印の上の朱印とバッジの行の両方に出る**（重複させる）。
朱印は「いま押された」瞬間の絵、バッジの行は「今日取れたもの」の一覧で、役割が違う。

## 5. バッジの軸（提案③）

いまの6個は全部「訪問数」の同じ軸で、しきい値が違うだけ。**軸を増やすと、出かける理由が増える**。

| 軸             | バッジ     | 条件                                                      |
| -------------- | ---------- | --------------------------------------------------------- |
| **作法**       | 満願       | どれか1つの寺社で12ヶ月連続                               |
| **旅のしかた** | 四季を巡る | 春(3〜5月) 夏(6〜8) 秋(9〜11) 冬(12〜2) それぞれに1回以上 |
|                | 1日に3箇所 | 同じ `visited_at` に**異なる寺社**が3つ以上               |
| **訪問数**     | 既存6個    | そのまま                                                  |

獲得バッジの画面は**軸でグループ化**する。見出しに一言添える
（作法 = 神社や寺に、もとからあるもの / 旅のしかた = 出かける理由を増やす）。

### 5-1. 採らなかったもの

| 案                 | 理由                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------- |
| 初めての県・県制覇 | **保存直後のチップで既に祝っている**（提案②）。バッジにすると二重                      |
| いちばん遠い場所   | 基準点に自宅が要る。プライバシーの話になるうえ、「地図の端」に言い換えても発明感が強い |
| 桜の季節           | ただの日付の範囲で意味づけが弱い。**四季を巡る**に置き換えた                           |

### 5-2. 条件の型を広げる

いまの `BadgeCondition` は `{ type: 'visit_count'; threshold: number }` の1種類。
満願と旅のしかたのために型を広げる。**この広げ方が③の本体**で、あとは軸を足すだけになる。

## 6. データ — スキーマ変更なし

`stamps` の `spot_id` と `visited_at DATE` で足りる。

| 要るもの          | 取り方                                                                            |
| ----------------- | --------------------------------------------------------------------------------- |
| その寺社の参拝月  | `select visited_at from stamps where user_id = ? and spot_id = ?`                 |
| あゆみの一覧      | ユーザーの全 `stamps` を `spot_id` でまとめる（既存の取得で賄えるか実装時に見る） |
| 四季 / 1日に3箇所 | 同じく全 `stamps` の `visited_at` と `spot_id`                                    |

## 7. やらないこと

- **通知は作らない**（`expo-notifications` は Phase 2）。入れるときも、本人が明示的に選んだ寺社だけ
- 毎日のストリーク
- 「あなたの連続記録」（アプリ全体で1本）
- 今月まだ参拝していないことを、こちらから言う
- バッジ自体をご褒美として見せること
- 寺（`temple`）で月参りを出さない、という区別は**しない**（作法としては神社が主だが、
  通っている人がいれば同じに扱う）

## 8. アクセシビリティ

- 12個の丸に `accessibilityLabel`「12ヶ月のうち7ヶ月、おまいりしました」
- **色だけで達成・未達を区別させない**。チップの「7ヶ月目」と結びの文が情報を持つ
- 満願の朱印とバッジの出現は `AccessibilityInfo.isReduceMotionEnabled` で止め、最終状態を出す
