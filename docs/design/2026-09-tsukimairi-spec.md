## 1. なぜこれだけ「連続」を入れていいか

**月参りは、アプリが発明した仕組みではなく、もとからある作法**。同じ神社に毎月1回参拝し、
12ヶ月続けると「満願」となって、神社が特別な御朱印をくれることがある。

| 論点       | Duolingo のストリーク | 月参り                 |
| ---------- | --------------------- | ---------------------- |
| 周期       | 毎日                  | **月に1回**            |
| 対象       | アプリ全体で1本       | **神社ごと**           |
| ご褒美     | アプリが発明した      | **神社が実際にくれる** |
| 決めたのは | アプリ（囲い込み）    | **その文化**           |

**アプリの仕事は、作り出すことではなく気づくこと。** だから v1 では
「月参りをする」と宣言させない。**参拝の記録から勝手に気づいて、カードを出すだけ**。

## 2. 定義

- **月参りの月数** = その寺社について、**連続する暦月に1件以上の `stamps` がある**月の数
- 同じ月に何枚記録しても **1ヶ月**
- 月が1つでも飛んだら、そこで連続は切れる（新しい連続が始まる）
- **12ヶ月で満願**

## 3. 出す条件

| 状態               | 表示                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| 連続 **0〜1ヶ月**  | **カードを出さない**。1回来ただけの人に「月参り」を名乗らせない       |
| 連続 **2〜11ヶ月** | カードを出す。「7ヶ月目」「満願まで、あと5ヶ月。」                    |
| **12ヶ月（満願）** | カードを満願の表示に切り替える。12個の丸が全部朱になり、「**満願**」  |
| 満願のあと         | そのまま数え続ける（13ヶ月目〜）。2周目として `満願 ×2` を出すかは v2 |
| **連続が切れた**   | §4                                                                    |

## 4. 途切れを罰しない

- **「連続が途切れました」のような赤い警告は出さない**
- 切れても「**この神社での最長は7ヶ月**」を実績として残し続ける
- 今月まだ参拝していないことを、こちらから言わない
- **通知は v1 では作らない**（`expo-notifications` は Phase 2）。通知を入れるときも、本人が明示的に選んだ寺社だけ

## 5. 見た目

| 要素       | 仕様                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| 置き場所   | `SpotDetailContent` の **`SpotSheetActions` の下・御朱印グリッドの上**。「ここでのあなたの記録」の文脈に置く |
| カード     | 白・角丸16・**上辺に3pxの朱 `#DC2626`**・影 `y2/blur6/9%`                                                    |
| 見出し     | 「月参り」16px/700。右に朱のチップ「7ヶ月目」                                                                |
| 説明       | 「毎月この神社へ。12ヶ月で満願です」12px `#4B5563`                                                           |
| 丸         | 12個を横一列（grid 12列・gap5・正方形の円）。達成 `#DC2626` / 次の1つ `#9CA3AF` の破線 / 残り `#E3E4E8`      |
| 両端の文字 | 左に開始月「3月」、右に「満願」10px `#9CA3AF`                                                                |
| 結び       | 罫線の下に「満願まで、**あと5ヶ月**。」13px（「あと5ヶ月」だけ朱の太字）                                     |

**言葉を借りる。**「12ヶ月連続バッジ」ではなく**満願**と呼ぶ。それだけでゲーム化ではなく作法の理解になる。

## 6. データ — スキーマ変更なし

`stamps` は `spot_id` と **`visited_at DATE`** を持っている。**これだけで足りる**。

```
select visited_at from stamps where user_id = ? and spot_id = ? order by visited_at
→ 年月（YYYY-MM）の集合にして、連続した月を数える
```

- `visited_at` は **DATE 型**なので、DB 側に時差の曖昧さはない
- ⚠️ **Issue #204 がこの機能の前提条件だった。** 記録した訪問日が1日ずれていた頃のままだと、
  **月末の深夜に記録した参拝が前月に入って連続が途切れる**。しかも本人には理由が分からない
- 既存の `fetchSpotStamps` 相当（スポット詳細の御朱印グリッド）と**同じ取得で賄えるか**を実装時に見る。
  賄えるなら**クエリを増やさない**

## 7. 満願のバッジ

`badges.ts` の6つは全部「訪問数」の同じ軸。**満願は別の軸の最初の1つ**になる。

- id: `mangan`、name: 「満願」、icon: ⛩、条件: **どれか1つの寺社で12ヶ月連続**
- `evaluateNewBadge` は `visit_count` の閾値しか見ないので、**条件の型を増やす**必要がある。
  提案③（バッジの軸を増やす）の入口になるので、**型を広げるところまでを④の範囲に含める**
- ご褒美はアプリのバッジではない。**本物の賞品は神社がくれる満願の御朱印**。文言もそう書く

## 8. やらないこと

- 毎日のストリーク
- 「あなたの連続記録」（アプリ全体で1本）
- 既定オンの通知で参拝を促すこと
- バッジ自体をご褒美として見せること
- 寺（`temple`）で月参りを出さない、という区別は**しない**（作法としては神社が主だが、通っている人がいれば同じに扱う）

## 9. 朝に確認したいこと

1. **カードを出す下限は「連続2ヶ月」でよいか**（1ヶ月では出さない）
2. **あゆみ画面にも月参りを出すか**。v1 は寺社の詳細だけに置く案。「湯島天満宮に7ヶ月」を あゆみ にも出すと、複数の寺社で通っている人には嬉しいが、画面が増える
