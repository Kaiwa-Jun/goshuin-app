# 要件: 見つからない寺社を、AI で調べて追加する

デザイン: **`docs/design/mockups/2026-09-spot-add-v1.html`**
関連: Issue #184（追加の動線を外した理由）
ステータス: **確定（2026-09-24 オーナー承認）**。みんなの地図への公開は「基準を満たせば自動」（2026-09-24 オーナー決定）

## 1. いまの実装（正確に）

| 項目         | 実装                                                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口         | **無い**。候補が無いと「候補が見つかりません」だけ（`SpotSelector.tsx:120`、#184 で外した）                                                     |
| 追加の中身   | `SpotAddModal`: 名前・神社/寺院の2つだけ。**座標はその場の端末の位置**（`SpotAddModal.tsx:40`）                                                 |
| 保存         | `createSpot` がクライアントから `status: 'pending'` で insert。RLS の INSERT は `authenticated AND status = 'pending'`                          |
| 見え方       | SELECT は `status = 'active'` だけ。**追加した本人にも見えない**。pending → active にする仕組みも無い                                           |
| マスタの項目 | `name` `lat` `lng` `type` `address` `prefecture` `rank`（既定 1）`status` `created_by_user_id` `merged_into_spot_id`                            |
| マスタの品質 | シード基準: 住所は情報源2つで確認・座標は住所から変換・都道府県の範囲内（`supabase/seeds/README.md`、`supabase/validation/validate_spots.sql`） |
| マスタの量   | **各県 20 件前後**（東京・宮城は多め）。載っていない寺社に当たるのは例外ではない → この動線がマスタを育てる主経路になる                         |

天龍寺・東福寺・鹿島台神社の座標がずれていたのは、端末の位置を座標にしていたため（記録したのが寺社でない場所だった）。

## 2. 決めたこと

1. **ユーザーの「ここです」は「私が行ったのはここ」の確認であって、マスタの正しさの確認ではない。** 自分用にはすぐ使えて、みんなの地図には裏付けが取れてから載る
2. **座標は住所から出す。** 端末の位置は座標にしない
3. **AI で見つからなくても記録は止めない。** 地図でピンを立てて自分用に保存できる
4. **みんなの地図への公開は、基準（§5）を満たせば自動。** 満たさなければ本人にだけ見える pending のまま、オーナーの確認待ちに入る
5. **位置情報はサーバーに送らない**（プライバシーポリシーの約束）。調べる手がかりは、端末上で市区町村名に直した**文字**として送り、画面に出して本人が直せるようにする
   - 市区町村名は、端末に取ってある**近くの寺社（マスタ）の住所**から取る（`areaLabel` と同じやり方）。OS の逆ジオコーディングは座標が Apple / Google に渡るので使わない
   - 近くに寺社が無い・位置が取れない・あとで家から記録している、のときは手がかり無しで全国から探し、候補に県と市を出して選んでもらう
   - 候補までの距離は、返ってきた座標と端末の位置から**端末上で**計算して出す

## 3. 流れ

```
検索で出ない
 └「〇〇を調べて追加」
     ├ 既存マスタに似た名前が近くにある → 「もしかして」で既存を出す（重複を作らない）
     └ 調べる（〜10秒）
         ├ 候補 1〜3件 → 「これですか？」→「ここです」→ 記録画面に戻り、その寺社が選ばれた状態
         │                               └ 裏で §5 を判定 → 公開 or 確認待ち
         ├ どれでもない / 見つからない → 地図でピン＋名前＋神社/寺院 → 自分用で保存
         └ 時間切れ・通信エラー → 同上（「調べずに地図で決める」はいつでも押せる）
```

## 4. 画面（試作 v1 の 4 枚）

| #   | 画面         | 中身                                                                                                                                                              |
| --- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ①   | 検索で出ない | 候補の一覧の下に「**「鹿島台神社」を調べて追加**」の行。似た名前が近くにあればその上に「もしかして」                                                              |
| ②   | 調べています | 下からのシート。「宮城県 大崎市 のあたりで探しています」（手がかりを出す・押すと直せる）。**「調べずに地図で決める」**を常に出す                                  |
| ③   | これですか？ | 候補カード（名前・神社/寺院・住所・小さな地図にピン・情報源の数）。主ボタン「**ここです**」、副「どれでもない」。注記「確かめられたら、みんなの地図にも載ります」 |
| ④   | 地図で決める | 地図の中心に固定ピン（地図を動かして合わせる）・名前・神社/寺院。注記「あなたの記録にだけ出ます」                                                                 |

記録画面に戻ったあとの選択済みの行は、既存の寺社と同じ見た目にする（「追加した寺社」などの印は付けない）。公開されたことの通知もしない。

## 5. 自動で公開する基準

すべて満たせば `status = 'active'`（`rank = 1`）。1つでも欠けたら `pending`（本人にだけ見える）。

| #   | 基準                                                                                              | 出どころ                          |
| --- | ------------------------------------------------------------------------------------------------- | --------------------------------- |
| P-1 | 住所を載せている**独立した情報源（ドメイン）が2つ以上**                                           | AI の調査結果（URL を返させる）   |
| P-2 | 住所から出した座標（国土地理院の住所検索 API）が、その**都道府県の範囲内**                        | `validate_spots.sql` と同じ判定   |
| P-3 | 近く（300m）に**似た名前の active が無い**                                                        | 名前の正規化 + 距離（規則で判定） |
| P-4 | 名前と種別が矛盾しない（「〜寺」「〜院」が shrine、「〜神社」「〜宮」「〜大社」が temple でない） | 規則                              |

地図で決めた寺社（④）は情報源が無いので、**自動では公開しない**。

## 6. 技術の形

| 部品                          | 変更                                                                                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Edge Function `research-spot` | 新規。入力: 名前・手がかり（都道府県・市区町村の文字）。Claude（ウェブ検索）で候補を最大3件、各候補に住所・種別・情報源 URL・公式サイト。座標は国土地理院 API |
| Edge Function `add-spot`      | 新規。候補（または④の手入力）を受け、§5 を判定して service role で insert。**クライアントからの spots への INSERT はやめる**（勝手に active を作れない）      |
| RLS（spots）                  | SELECT に `created_by_user_id = auth.uid()` を足す（本人には pending も見える）。INSERT ポリシーは落とす                                                      |
| `fetchVisitLog` などの結合    | 本人の pending が見えるようになれば、御朱印帳から消える問題（#184 の併発）も解ける                                                                            |
| `spot_info_sources`           | 公式サイトが取れたら `official` で入れる → 限定御朱印のクローラーの対象が自然に増える                                                                         |
| 回数の上限                    | 1人 1日 10 回まで（ウェブ検索の費用と悪用よけ）                                                                                                               |

費用の目安: Haiku 4.5 + ウェブ検索数回で、1件あたり数円。

## 7. 規約・ポリシー

- **プライバシーポリシー**: 「スポットを追加するとき、調べる手がかりとして入力した名前と市区町村名を Anthropic に送る」を足す（位置情報そのものは送らない）
- **利用規約**: 「ユーザーコンテンツ」の節に「追加したスポットの情報は、他のユーザーの地図にも表示されることがあり、アカウント削除後も残る」を足す（`created_by_user_id` は退会で NULL になる既存の挙動）

## 8. 既存の3件

天龍寺・東福寺・鹿島台神社（pending、座標は 2026-09-24 に修正済み）は、`add-spot` と同じ §5 の判定を当てて、満たせば active にする。

## 9. やらないこと

- ユーザーによる既存スポットの編集・修正の提案
- 何人も記録したら rank を上げる
- 公開されたことの通知
- オーナー用の確認画面（当面は SQL / ダッシュボードで `pending` を見る）
