# Issue #301: 寺社と Wikidata の対応表をつくる（#292 第2弾の座標と、帯の写真の土台）

## 概要

寺社のマスタ（seed の 1,109 件）を Wikidata の項目に結びつける**対応表**と、Wikimedia Commons の**写真の候補**を、リポジトリに残る形で作る。あわせて、#292 第2弾のための「オーナーが地図で座標を選ぶ画面」を作り直す。

- 作るスクリプトは `supabase/scripts/spot-wikidata/`（Deno）。判定は純関数で、テストで固める
- 公開してよい結果（seed の名前・都道府県と、Wikidata・Commons の情報だけ）を `supabase/data/` に置く: 対応表 `spot-wikidata-301.json`、写真の候補 `spot-photos-301.json`
- API の生の応答・地理院と OSM の座標・画面のデータ・オーナーの選択は、リポジトリの外の `~/goshuin-work/spot-wikidata/`（消えない場所）に置く。取り直しは途中から再開できる
- 画面はローカルのサーバー（`127.0.0.1`）で開く。選んだ結果は、今の `supabase/scripts/spot-coords/main.ts import-owner` にそのまま渡せる JSON で書き出す
- **本番には触らない**。migration・seed・確かめる SQL・台帳 `spot-coords-292.json`・`spot-coords` のスクリプトは変えない。本番の座標を直すのは第2弾の PR（`spot-coords` で生成）

背景: 2026-09-27〜28 の突き合わせの材料（`decisions-draft.json`・`audit.json`・`review-owner.html` など）を scratchpad に置いていて、macOS の定期処理で消えた（2026-10-03 に確かめた。フォルダの形だけ残り、ファイルは 0 件）。第2弾の 117 件の区分（確かさ 中 60・国土地理院由来 12・取り違え 1・オーナーが選ぶ 17・要調査 27）は**再現しない**。この契約の規則（D-9）で分け直し、数は S4 で README に書く。

> **2026-10-03 リーダーの判断**: 「決めてもらうこと」は次のとおり。① オーナーが地理院の地図を見て自分でピンを置ける（`owner`）② `import-owner` が書き出しの `ref` を読むのは第2弾の PR ③ `medium` の結びつきも写真の候補に入れ、`linkConfidence` を付ける ④ MapLibre GL JS は CDN から版を固定して `integrity` 付きで読む ⑤ 距離の目安は書いたとおり（S4 の件数を見て見直す）⑥ S4（本物の取得）は**オーナーではなく実装する人が流す**。`SPOT_WIKIDATA_CONTACT` は公開のリポジトリの URL `https://github.com/Kaiwa-Jun/goshuin-app`（リポジトリはすでに公開で、9/27 の調べものでも同じ User-Agent を使った）。値はコミットせず、流すときに環境変数で渡す。オーナーの手順は O-1〜O-6（選ぶ画面）だけ
