# Issue #275: 御朱印帳の写真の読み込み中を、画像の枠の中の動きで見せる

## 概要

御朱印帳の画面（めくる表示・タイル表示）では、御朱印の写真が届くまで紙が白（めくる表示）・灰色（タイル）のままで、読み込み中なのか分からない。オーナーの要望で、**画面全体ではなく画像の枠の中だけ**で読み込み中と分かるようにする。

1. **めくる表示**（`GoshuinchoPage`）: 写真が届くまで、紙の枠いっぱいに和紙の色の下地と薄い枠を敷き、真ん中で**小さな御朱印帳がめくれ続ける**（布の表紙・見開きの紙・紙の厚み・綴じ目の陰・めくれる紙の表裏と陰・下のページに落ちる影。ひとめくり 0.85秒 → 間 0.65秒。めくるたびに右のページに次の朱の印が現れる）。**動かすのは画面に出ているページと両隣だけ**
2. **タイル表示**（`GalleryScreen`）: 写真が届くまで、和紙の色の下地と薄い枠を敷き、**すべての下地がそろって**ゆっくり明滅する（1周 1.6秒）
3. どちらも、写真が届いたら **0.25秒でふわっと**写真に入れ替える。視差効果を減らす がオンなら動かさず、入れ替えも即時
4. **動きの時計はアプリで1本だけ**。読み込み中の枠が1つも無くなったら止める（止まらないアニメーションがネイティブのメモリを食い潰した #99 追補3 の教訓）

新しいネイティブの部品は足さない（`package.json` の差分なし）。View・`expo-linear-gradient`・`react-native-svg`（`Seal` が使っている）・RN の `Animated` で作る。

## テスト方針

- **時計はモジュールに1つ**なので、テストの前後で `resetLoadingClockForTests()` を呼ぶ。`Animated.loop` は `SavingOverlay.test.tsx` と同じく `jest.spyOn(Animated, 'loop')` で**呼ぶたびに新しいスタブ**（`start`・`stop`・`reset` が `jest.fn`）を返し、スタブごとに start / stop を数える。「1本だけ」は**「start の回数 − stop の回数」がどの時点でも 0 か 1**で見る（めくる表示は開いた直後に `currentIndex` が 0 から最後へ飛ぶので、登録が 2 → 0 → 2 と動いて loop を作り直すことがある。これは想定どおりで、回数そのものは縛らない）
- **時計の値を動かして見る検査は、`Animated.loop` をスタブにして行う**（本物の loop が始まると `loadingClock` がネイティブ扱いになり、同じファイルの後のテストで `setValue` が描画に届かなくなることがある）。値は `act(() => loadingClock.setValue(t))` で動かし、style の中のノードを `__getValue()` で読む（`GoshuinchoFlipView.test.tsx` の `rotateOf`・`RecordArt.test.tsx` の `opacityOf` と同じ読み方。値そのものが入っていればそれを読む）。回転は `parseFloat` して数で比べる（小数3桁）
- ふわっとは `jest.spyOn(Animated, 'timing')` で引数を見る。消え終わりは `HeroFlyer.test.tsx` と同じく、スタブの `start(cb)` で `cb({ finished: true })` を呼んで進める。時計の `Animated.timing(loadingClock, …)` も同じスパイに入るので、下地の検査では**第1引数が `loadingClock` でない呼び出し**を見る
- 写真の知らせは `fireEvent(getByTestId('flip-page-image-…'), 'load', { nativeEvent: { source: { width: 600, height: 800 } } })` / `fireEvent(…, 'error')`（Jest の `Image` はモック。知らせは props を呼ぶだけ）
- 並びは `getAllByTestId(/正規表現/)` が木の順に返すことを使う（#272 と同じ）。見た目は `StyleSheet.flatten(el.props.style)` で値を見て、色は `colors` のトークンで比べる。`LinearGradient` は `jest.setup.js` のモック（props をそのまま持つ View）なので `colors`・`locations`・`start`・`end` を props で見る。`Seal` は包みの View の中を `UNSAFE_getByType(Seal).props` で見る
- 視差効果を減らす は `jest.spyOn(AccessibilityInfo, 'isReduceMotionEnabled').mockResolvedValue(true)`・`addEventListener` のスパイで handler を取り出して途中の切り替えを起こす（`SavingOverlay.test.tsx` と同じ）
- **動きの手触り（向き・速さ・印の切り替わり・明滅のそろい方）はシミュレータ**（UI-8〜12・native-only）。Expo Web は読み込みを止めて形と「動いている／止まっている」を見る（UI-4〜7）

## リスク・不確実な点／申し送り

- **Android と新しい C++ の Animated の実装で、`modulo` と段の補間を確かめていない**。iOS はコード（`RCTAnimationUtils.mm`）を読んで、幅 0 の区間を選ばないことと割り算の形を確かめた。段は念のため幅 1ms の傾きにした（D-5）。Android を出すときに実機で UI-8・UI-9 をやり直す
- **向きの符号**: CSS の `rotateY(-θ)` と RN の `rotateY` が同じ向き（紙が手前に起き上がる）かは、コードでは確かめていない。`GoshuinchoFlipView` は `inverted` の FlatList の中だが、セルごとに反転し直しているので本は反転しない見込み。UI-8 で確かめ、逆なら `leafRotateY` の符号だけ直す（fix のコミット）
- **72 秒の loop**: ネイティブの timing は start のたびに 60fps ぶんの値の列（約 4,300 個）を1回だけ渡す。めくる表示を開いた直後の登録のし直し（D-2 のテスト方針）で1回余分に渡ることがある。気になる重さではない見込みだが、UI-8 の録画で開いた直後に引っかかりが無いかを見る
- **御朱印帳へ戻るたびの下地**: `useGalleryStamps` はフォーカスのたびに取り直し、その間 `ActivityIndicator` に置き換わるので、戻るたびに一覧の部品が作り直される。キャッシュ済みの写真でも `onLoad` が JS に届くまでの 1〜数フレームは下地が出て、そこから 0.25秒ふわっと写真になる。UI-13 で記録する。気になるなら「マウントからすぐ届いたら即時に外す」か「キャッシュを先に調べる」を別の Issue で
- **動いている本の重さ**: 動く本は最大3冊で、1冊に `Seal` 12個・`LinearGradient` 8個（表紙1・紙の厚み2・綴じ目の陰2・落ちる影1・紙の陰2）・`Svg` 1個。止まっている本は最大2冊（`Seal` 4個）。3つ以上離れたページは本を描かない（D-9）。古い端末での重さは確かめていない
- **他のタブにいる間も時計が回りうる**: 下のタブは画面を外さないので、写真がまだ届いていないまま他のタブへ移ると、届くか失敗するまで時計が回る。iOS の読み込みはいずれ成功か失敗（タイムアウト）で終わるので、回り続けることは無い見込み（ずっと届かない要求があったときのタイムアウトの長さは確かめていない）
- **Expo Web の読み込みの止め方**は RN Web の `ImageLoader` の中の作り（`new window.Image()` の `onload`）に依存する。`react-native-web` を上げると効かなくなりうる
- **Web の `Image` は、ハンドラが描画のたびに新しい関数だと読み直して `onLoad` を何度も呼ぶ**（`useEffect` の依存に `onLoad` が入っている）。D-11 で URL ごとに持つので結果は変わらないが、`rememberAspect` は何度も呼ばれる（今と同じ）
