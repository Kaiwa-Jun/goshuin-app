# Issue #276: 御朱印帳の表示の切り替えボタンと、切り替わりの動きを付ける

## 概要

御朱印帳タブの見出しの右にある表示の切り替え（めくる表示 / タイル表示）は、今は2つのアイコンが裸で並び、選んだ方が橙になるだけ。オーナーの要望で、下のタブのアイコンのように動きのある切り替えにし、切り替えたときの中身にも動きを付ける。

1. **切り替えボタン（A スライドする台）**: 灰色の台の中を白い台がばねですべって移る（少し行き過ぎて戻る）。選んだアイコンが動く（めくる = 本が開く、一覧 = タイルが1枚ずつ並ぶ）。場所は今のまま（見出しの右）、高さも今のまま（44）
2. **切り替わりの動き（5 束から、めくれながら並ぶ）**: めくる → 一覧は、見ていたページが縮んで束になり、そこから投稿が1枚ずつくるりとめくれながら（紙の裏を見せながら）自分の場所へ散って並ぶ。見ていた1枚は束のいちばん上から最初に着く。一覧 → めくるはその逆で、めくれながら真ん中に集まって束になり、その1枚がページに広がる。中身の動きは 0.565秒 / 0.59秒
3. 動かすのは画面に見えているタイルだけ（隠れているタイルは置くだけ）。写真の読み込み中（#275 の和紙の下地）でも同じ動きで切り替わる
4. 視差効果を減らす がオンなら動かさない（すぐ切り替える）。止まらないアニメーションは作らない（#99 追補3）

新しいネイティブの部品は足さない（`package.json` の差分なし）。RN の `Animated`（`timing`）・`transform`・`backfaceVisibility` で作る。

## テスト方針

- **曲線と値は純関数で縛る**（`viewModeMotion.test.ts`）。補間は `new Animated.Value(0)` から作り、`setValue(t)` のあと style に入るノードを `__getValue()` で読む（#275 と同じ読み方。回転は `parseFloat`）。値の検査は刻んだ点（k ÷ 16）の上で行う（点の間は直線なので、点の上でなら式と一致する）
- **ボタン**は `jest.spyOn(Animated, 'timing')` で呼ぶたびにスタブ（`start`・`stop`・`reset` が `jest.fn`）を返し、第1引数と設定を見る。値は `__getValue()` で読む
- **画面の動き**（`GalleryScreen.test.tsx` の新しい describe）: `jest.useFakeTimers()`（`requestAnimationFrame` と 300ms のタイマーを進める）。`Animated.timing` はスタブ（時計の timing は設定の `duration` が 565 か 590 のもので見分け、第1引数を時計として `act(() => clock.setValue(t))` で進める。終わりはスタブの `start` のコールバックに `{ finished: true }` を渡す）。`Animated.loop` は今の `beforeEach` のスタブのまま。`measureInWindow` は `jest.spyOn(View.prototype, 'measureInWindow')` で、`this.props.testID` ごとに矩形を返す（RN の Jest の View は `MockNativeMethods` を prototype に持つ。`Animated.View` の ref でも同じ関数に届くことを確かめた）。describe の終わりで戻す。レイアウトは `fireEvent(el, 'layout', { nativeEvent: { layout } })`・`fireEvent(el, 'contentSizeChange', w, h)` で起こす
- **動きの検査の準備**（下の AC で「準備」と書くもの）: W = `Dimensions.get('window').width`・T = (W − `spacing.lg` × 2 − `spacing.xs` × 2) ÷ 3・P = `computePageLayout(W).pageWidth`・S = T ÷ P。御朱印 15 枚 `s0`〜`s14`（`image_path` は `user-1/stamp-{i}.jpg`・`isLoading: false`）。`measureInWindow` の矩形: `gallery-flip-pane` → (0, 100, W, 1000)・`flip-page-surface-{id}` → ((W − P) ÷ 2, 250, P, 1.5P)・`gallery-list-viewport` → (0, 140, W, 960)・`gallery-tile-motion-s{i}` → (16 + (i mod 3)(T + 4), 140 + floor(i ÷ 3) · 300, T, T)・ほかは (0, 0, 0, 0)。このとき束の中心は (W ÷ 2, 250 + 0.75P)、見えているタイルは `s0`〜`s11`（4行目 `s9`〜`s11` は下の端に一部だけかかる）、`s12`〜`s14` は見えていない。手順: 描く → `gallery-content` に `layout`（W × 1000）→ `flip-list` に `momentumScrollEnd`（`contentOffset.x = 4 · snapInterval`）でページ 4（`s4`）へ → `view-mode-grid` を押す → `gallery-list` に `layout`（高さ 960）と `contentSizeChange`（W, 1532。rowH = 300・offset は 0 で送らない）→ `act(() => jest.advanceTimersByTime(50))`。dx_i・dy_i は D-10 の式で、この矩形から出す
- 既存の検査は変えない（D-9 の ④）。**動きの手触り（ばねの行き過ぎ・裏の見え方・束のいちばん上・時間）はシミュレータ**（UI-6〜13・native-only）。Expo Web は値の流れと順番・終わりの形を見る（UI-1〜5）

## リスク・不確実な点／申し送り

- **新しいアーキテクチャ（Fabric）での測り方**: `measureInWindow` は影の木の位置から出す。`scrollToOffset` を送った直後は、ネイティブのスクロールの位置が影の木に届くまでに間があり、2フレーム待っても古い位置が返るかもしれない。そうなるとタイルが束からずれた所から飛び、着いたあとに跳ぶ。UI-6 の「着いたあと跳ばない」で見る。跳ぶなら、送った offset が `onScroll` で返ってくるのを待ってから測る形に直す（fix のコミット）
- **仮想化**: 一覧を遠くへ送った直後は、見える範囲の行がまだ描かれていないことがある。見ていた1枚が描かれるまでは待つが、ほかの行が遅れて描かれたら、その行のタイルは動かずに現れる。UI-13 で見る
- **準備の時間**: 入ってくる側を描いて測るまで、中身の動きの始まりが遅れる（ボタンの台はすぐ動く）。押してから止まるまでの上限を 0.8秒にした（UI-8）。超えるなら、一覧の面を描くときの重さ（`GalleryTileImage` と下地の数）を見る
- **束のいちばん上の zIndex**: `CellRendererComponent` の zIndex が iOS（Fabric）でスクロールの中のセルの重なりに効くかはコードでは確かめていない。効かないと束のいちばん上が紙の裏になる（見ていた1枚はその下から最初に出ていく）。UI-6 の最初のコマで見る
- **iOS の裏返し**: #275 と同じく、ちょうど 180° を避けて 179.9° にした。表と裏は兄弟の2枚。`perspective: 700` と 2D の傾き（親）の組み合わせで裏の面が正しく出るかは UI-6 で見る
- **写真の食い違い**: 束のいちばん上（小さい写真・cover）とページ（元の写真・contain・たいてい読み込み中）が違うので、一覧 → めくる で束がページに替わる瞬間に絵が替わる（D-18）。オーナーに先に伝える
- **ボタンの幅が 6pt 広がる**（88 → 94）。高さは今のまま（見出しの高さ・中身の位置は変わらない。UI-1）
- **開く位置が変わる**: ボタンで切り替えたとき、一覧は見ていた1枚の行で開き（今は初回だけいちばん下、2回目以降はいちばん上）、めくる表示は一覧で開いて閉じた御朱印か一覧の真ん中の御朱印で開く（今はいつも最新。オーナーの判断 2026-09-27）
- **Web の値の集め方**は RN Web が transform・opacity を要素の `style` に書くことに依存する（#275 の UI-6 と同じ）。`react-native-web` を上げると読み方が変わりうる
- **Android と C++ の Animated の実装で、刻んだ補間と 1ms の傾きを確かめていない**（#275 と同じ）
