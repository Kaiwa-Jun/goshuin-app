# Issue #245: あゆみに、暮らしの中で踏み出せる「もう少し」を出す

## 概要

あゆみの一番上に **「もう少し」カード**（最大3行）を置く。**暮らしの中で踏み出せる一歩だけ**を促す。

| 行             | 出す条件                                                          | 押すと             |
| -------------- | ----------------------------------------------------------------- | ------------------ |
| 巡礼           | 残り **1〜2社** のコース                                          | 巡礼の詳細         |
| 月参り         | いま続いていて、満願まで **1〜3ヶ月**、**今月まだ参拝していない** | 地図でその寺社     |
| 印             | 次の印まで残り **2割以内**（四季の印は **あと1つ**）              | 印の欄へスクロール |
| よく行くエリア | 参拝した **月が3ヶ月以上** あるエリアに、まだの寺社がある         | エリアのシート     |

- 地方の制覇・都道府県は**促さない**。地図は今のまま（点線・「あと◯県」は付けない）。**地方の帯は足さない**（Issue #209 で「地図が県単位で同じことを見せる」として地方別の表示を消した判断を守る。v3 の注記にあった帯は、実装時にこの衝突が分かって外した）
- 「よく行くエリア」は**端末の位置情報を使わず、記録した寺社の位置から**割り出す。画面で「家」「あなたの位置」とは言わない
- 通知はしない

背景: 2C 向けに「開きたくなる」仕組みが要るが、毎日参拝する人はいない。月参りが効いているのは「近い・周期がある・労力が小さい」から。「関東 あと2県」は旅行レベルの労力で、見るたびに「できていないこと」を突きつける（オーナーとの議論 2026-09-24）。

## 詳細設計

### データ

| 使うもの   | 出どころ                                                | 変更                                                            |
| ---------- | ------------------------------------------------------- | --------------------------------------------------------------- |
| 月参り     | `tsukimairiList(visitLog, today)`                       | なし                                                            |
| 印         | `buildBadgeProgress` / `nearestUnearned` / `distanceOf` | なし                                                            |
| 巡礼       | `fetchPilgrimageProgress`                               | **`unvisitedSpotIds` を足す**（エリアの一覧から重複を外すため） |
| 参拝の記録 | `fetchVisitLog`                                         | **寺社の `lat` / `lng` / `address` / `prefecture` を足す**      |
| まだの寺社 | `fetchSpotsByBounds(getBoundingBox(中心, 5km))`         | なし（既存）                                                    |

### よく行くエリアの割り出し（純関数 `frequentArea`）

1. 参拝の記録を、**5km 以内**で貪欲にまとめる（中心は所属する記録の平均）
2. まとまりごとに、**参拝した月（`YYYY-MM`）の数**を数える。枚数ではなく月（旅行1回で10枚集めても1〜2ヶ月にしかならない）
3. 月が **3以上** のまとまりのうち、月が一番多いもの（同数なら記録の多い方）を「よく行くエリア」にする。無ければ出さない
4. 名前は、そのまとまりの寺社の住所から一番多い市区町村（`〇〇市`、東京23区は `〇〇区`、町村は `〇〇町/村`）。取れなければ都道府県。表示は「**〇〇のまわり**」（`市` などは落とす: 仙台市 → 仙台）
5. まだの寺社: 中心から 5km 以内・`status = active`・**ランク3以上**・まだ記録していない寺社。**巡礼の行に出ている残りの寺社は数えない**（シートでは薄く添える）。近い順に最大5件
6. まだの寺社が0なら、その行は出さない

### 並べ方

- 巡礼 → 月参り → 印 の中で「あと」の数が小さい順（同じならこの順）。よく行くエリアは「あと」が無いので最後
- 最大3行。1行も無ければ**カードごと出さない**（「まだ何もありません」とも言わない）

## テスト方針

- `frequentArea` / `mouSukoshi` は純関数としてテストで固定（本アカウントの試算: 仙台 7ヶ月・京都 2ヶ月＝旅行は入らない、を再現するケースを含む）
- カード・シート・帯はコンポーネントテスト（何を出すか・出さないか・押したときの遷移）
- 既存の月参り・印・巡礼の表示は変えない（既存テストが通る）

## 受入基準（Acceptance Criteria）

### 機能基準（純関数）

- [ ] AC-1: 5km 以内の記録が1つにまとまり、参拝した月が3以上のまとまりだけが「よく行くエリア」の候補になる
- [ ] AC-2: 1回の旅行で同じ月に10枚あるまとまり（月=1）は、記録が多くても候補にならない
- [ ] AC-3: 候補が複数あれば、月が一番多いものを選ぶ。同数なら記録が多い方
- [ ] AC-4: エリア名は住所の市区町村から付く（「宮城県仙台市青葉区…」→「仙台」、「東京都千代田区…」→「千代田」、「宮城県柴田郡村田町…」→「村田」）。住所が無ければ都道府県から（「宮城」）
- [ ] AC-5: 巡礼は残り1〜2社のコースだけが行になる（残り0・3以上は出ない。スポット0のコースも出ない）
- [ ] AC-6: 月参りは、いま続いていて満願まで1〜3ヶ月で、今月の参拝がまだのものだけが行になる（今月すでに参拝済み・満願済み・途切れたものは出ない）
- [ ] AC-7: 印は、次の印（`nearestUnearned`）が残り2割以内のときだけ行になる。四季の印は残り1つのときだけ
- [ ] AC-8: 行は最大3。巡礼・月参り・印は「あと」の小さい順、同数は 巡礼 → 月参り → 印。エリアは最後
- [ ] AC-9: エリアのまだの寺社から、行になっている巡礼の残りの寺社を除く。まだの寺社が0ならエリアの行は出ない
- [ ] AC-10: 何も当てはまらなければ、行は0件になる
