# Issue #302: 地図のピンのシートの帯に寺社の写真を出す（#293 第2段・Wikimedia Commons・R2）

## 概要

#293（第1段・写真なしの帯）の帯に、Wikimedia Commons の寺社の写真を出す。写真の無い寺社・写真を読めないときは第1段の空押しのまま。

1. **写真の候補を絞って人が選ぶ**: #301 の `supabase/data/spot-photos-301.json`（868 寺社・898 ファイル）から、機械の規則で 733 寺社・755 ファイルに絞り（D-5）、ローカルの画面（#301 の `serve` と同じ形）で 1 寺社 1 枚を選び、見せたい縦の位置 `focus_y` を決めて承認する。承認したものを公開の台帳 `supabase/data/spot-photos-302.json` に書き出す
2. **R2 に置く**: 承認した写真を Commons から幅 1280 の縮小版で取り（実装する人。User-Agent は環境変数）、`goshuin-images` バケットの `spot-photos/<sha1>.<拡張子>` に置く（オーナーの鍵。H）
3. **DB に持つ**: 新しい表 `spot_photos`（1 寺社 1 行・`spots.id` に結ぶ・RLS で承認済みだけ読める）。中身は台帳から作る migration（#292 と同じく名前・都道府県・作成者なしで 1 行に絞る）
4. **アプリ**: `SpotSheetHero` に写真の地を足し、行った寺社は写真に自分の御朱印のページを挟む（試作 `RECT.tuck`）。つまみを白くし、帯の左下の ⓘ を押すと撮影者・ライセンス・元の写真・トリミングの注記を吹き出しで出す。写真は `img.goshuinsanpo.com` の変換 URL（幅 1200）で読む

見た目は**オーナーが実機で OK を出した試作（ブランチ `preview/302-photo-band`。#295 の上の 71eaeab・315e5c8・df37201）を正とする**。試作から替えるのは次の2つだけ: ① 写真を upload.wikimedia.org から直接読む → R2 の変換 URL ② 表を「都道府県/名前」で引く → DB の `spot_id` で引く。

新しいネイティブの部品は足さない（`package.json` の差分なし。`Modal`・`Linking`・`@expo/vector-icons` は今あるもの）。

### 画面仕様（アプリ。値は試作のまま）

#### 写真のある寺社（地図 → ピン / 検索 → シートが半分で出る）

- 写真が届くまでは第1段の帯（和紙・空押しの印・灰色のつまみ）。届いて読めた描画で写真の地に替わる（動きなし）。つまみが白く（薄い影）なる。帯の左下（名前の行のすぐ上）に小さな ⓘ（薄い墨の丸に白い i）
- 写真は幅いっぱい。`focus_y` の所が、帯の見えている所（半分 80・大きく 208 から名前の行 30 を除いた所）の真ん中に来るように縦にずらす。端は帯の外に出さない
- 大きく開くと、ずらす量がシートの位置に合わせて連続に変わる（指について動き、放すと今の spring）

#### 行った寺社で写真がある

- 写真の右下に自分の御朱印のページが挟まる（白い縁・濃い影）。半分では右上の小さな束（幅 34）、大きく開くと名前の上まで降りてくる（幅 80）。回数で後ろに重なる（3枚まで）は第1段のまま。朱の跡は写真の下で見えない

#### ⓘ を押す

- ⓘ が少し濃くなり、ⓘ の上に白い吹き出し（幅 292・左 10）。撮影・ライセンス（リンク）・元の写真（Wikimedia Commons のリンク）・「帯に合わせてトリミングしています」。リンクを押すとブラウザで開く。ほかの所を押すと閉じる。視差効果を減らす がオンなら、吹き出しはふわっとせずに出る

#### 写真の無い寺社・読めない写真

- 第1段の帯のまま（ⓘ もつまみの白も無い）

## リスク・不確実な点／申し送り

- **本番の SQL の大きさ**: 台帳 700 件ほどで、migration は 250KB 前後の1文になる見込み（#292 は 61KB が通った）。`db query --linked` で大きすぎて断られたら、H-11 で止まる（`DO` ブロックなので本番は変わらない）。そのときは生成器で弾を分ける（第1弾・第2弾…）
- **Commons の縮小版の幅**: Wikimedia は決まった幅の縮小版を求める方向で、1280 は試作で読めた。`fetch` で 429 が続くときは止めて渡す（待ち時間を延ばすのはリーダーの判断）
- **変換の `Accept`**: `format=webp` でも `Accept` に `image/webp` が無いと JPEG が返る（#227 S1）。iOS の RN の `Image` が何を送るかは L-1 と H-15 のあと、必要なら実機の通信で見る。表示できない形式は返らない
- **ユニーク変換の数**: 帯の写真で最大 733/月が増える。御朱印の 1200 / 400 と合わせて月 5,000 を超えるかは、Cloudflare の Images の使用量で月に一度見る
- **選び間違い**: 733 件を人（リーダー）が1枚ずつ見るので、別の寺社の写真・人の顔が主の写真が残りうる。AC-39 の抜き取りと、`withdrawn` で後から外せることで受ける
- **同じファイルを持つ寺社**（3組）: 甲斐國一宮浅間神社 と 浅間神社（一宮）は seed で同じ神社が2行の可能性がある（この Issue では直さない）
- **吹き出しの位置**: `measureInWindow` は iOS で確かめる（UI-3 は Web）。Android は見ていない
- **#295 の直し**: 積んでいる間に #295 が変わると、載せ替えで `SpotSheetHero` / `SpotBottomSheet` がぶつかりうる
- **R2 のキーの決まり**: `spot-photos/` は `<user_id>/` の形でないので、`delete-account`（`<id>/` の下だけを消す）・`sign-stamp-upload`（`<user_id>/` の下だけに署名）・`r2-copy`（原本の形だけを写す）のどれにも触れられない。#227 AC-7（`thumb-400/`・`view-1200/` を含むキーが無い）にも当たらない
