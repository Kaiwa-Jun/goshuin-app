# Issue #130: P1-02 記録フローの最短化

## 概要

御朱印の記録フローから**確認モーダルを廃し、写真をカメラ直起動にし、境内にいるときは最寄りスポットを既定選択する**。地図 FAB 経路を **7 タップ → 3 タップ**（自動選択が効く典型ケース）にする。

タップ数を削るレバーは3本あり、**モーダル廃止だけでは 7→6 にしかならない**ため3本すべてを本 Issue で扱う。

```
現状（地図 FAB 経路・7タップ）              本 Issue 後（境内にいる場合・3タップ）
──────────────────────────────          ──────────────────────────────
1. FAB (+)                               1. FAB (+)
2. スポット検索欄をタップ                    （最寄りが既定選択済み・変更可）
3. 候補スポットをタップ
4. 写真枠をタップ                          2. 写真枠をタップ → カメラが直接起動
5. 「カメラで撮影」                           [OS: シャッター → 写真を使用]
   [OS: シャッター → 写真を使用]
6. 「この内容で記録する」                    3. 「この内容で記録する」
7. 「登録する」（ConfirmModal）                 → 完了画面（取り消し可）
```

- GitHub Issue: #130（P1-02）
- ブランチ: `feature/issue-130-record-flow-shortening` → develop
- 監査根拠: `docs/design/ux-audit-2026-08.md` の B-1 / D-3

### タップ数の定義

**アプリ内のタップのみを数える。** OS が出す UI（カメラのシャッター、写真ライブラリの選択、権限ダイアログ）は数えない。この定義は監査 B-1 と同じ。

## 決定事項（D-3）

**確認モーダル（`ConfirmModal`）は廃止し、記録完了画面に取り消し導線を出す。** 2026-08-09 にユーザーが決定。

判断根拠:

- モーダルが表示するのは**スポット名と訪問日だけ**（`ConfirmModal.tsx:38-48`）。どちらも直前のフォーム上に見えている
- **一番間違えやすい「写真」を確認していない**ため、誤登録防止の効果が元々薄い
- `deleteStamp` / `deleteStampImage` が実装済み（`services/stamps.ts:164,169`）で、取り消しの実装コストが低い
- `evaluateNewBadge` は純関数で DB 永続化が無い（バッジのテーブルが存在しない）ため、取り消し時にバッジ剥奪の考慮が不要

## 詳細設計

### S-1: `ConfirmModal` の廃止

`RecordScreen.tsx` の現状:

```
handleSavePress() → form.validate() → setShowConfirm(true)
                                          ↓ ConfirmModal「登録する」
                                      handleConfirm() → form.submit() → navigate('RecordComplete')
```

変更後: `handleSavePress()` が `handleConfirm()` の中身をそのまま実行する。`showConfirm` state と `ConfirmModal` の描画を削除する。

- `form.submit()` は内部で `validate()` を呼ぶ（`useRecordForm.ts:115`）ので、二重の `validate()` 呼び出しは残さない
- 送信中の二重タップは既存の `disabled={form.isSubmitting}`（`RecordScreen.tsx:239`）で防がれる。**この防御は維持する**
- `src/components/record/ConfirmModal.tsx` とそのテストを削除する

### S-2: 記録完了画面の取り消し

`deleteStamp(stampId, imagePath)` に両方が要るため、`RecordComplete` の nav params に **`stampId` と `imagePath` を追加**する。

```ts
RecordComplete:
  | {
      stampImageUrl?: string;
      spotName?: string;
      visitCount?: number;
      badge?: { name: string; description: string } | null;
      stampId?: string;      // 追加
      imagePath?: string;    // 追加
    }
  | undefined;
```

**取り消しの挙動**:

1. 「記録を取り消す」をタップ → `Alert.alert` で確認（「取り消すと写真ごと削除されます」）
2. 確認 → `deleteStamp(stampId, imagePath)`
3. 成功 → 記録画面を飛ばして地図へ戻る（`navigate('MainTabs', { screen: 'MapTab', ... })`）
4. 失敗 → `Alert.alert` でエラー原文を出す。画面には留まる（記録は残っている）

**取り消しに確認 Alert を出す理由**: 取り消しは非可逆で、redo をスコープ外にしている。主導線ではないためタップ数の目標に影響しない。

**表示上の扱い**: 「記録を取り消す」は他の3ボタン（もう1枚記録する / 地図を見る / あつめるを見る）より**下**に、控えめなスタイル（テキストのみ・`colors.white` の低不透明度）で置く。誤タップを避けるため他ボタンと間隔を空ける。

**`stampId` が無い場合**（旧来の遷移や params 欠落）は取り消しボタン自体を描画しない。

#### 受容する副作用

`form.submit()` は `triggerExtraction(stamp.id)` を fire-and-forget で呼んでいる（`useRecordForm.ts:142`）。**取り消し時点で AI 抽出が既に走っている可能性がある**が、これは受容する。抽出結果はスポット単位の情報であり、stamp が消えても実害が無いため。抽出のキャンセル機構は作らない。

### S-3: カメラ直起動

`PhotoPickerModal` を削除し、権限ハンドリングを **`usePhotoPicker` フック**に集約する。

```ts
// src/hooks/usePhotoPicker.ts
export function usePhotoPicker(): {
  takePhoto: () => Promise<string | null>; // カメラ。権限が無ければ設定導線の Alert を出して null
  pickFromLibrary: () => Promise<string | null>; // ギャラリー
};
```

- 権限拒否時の Alert（「カメラを使えません」+「設定を開く」）は `PhotoPickerModal.tsx:29-40` の実装をそのまま移植する。**iOS は一度拒否されると OS ダイアログが二度と出ない**ため、この導線は必須
- 例外時の Alert（`describeError`）も移植する
- 画面側: 写真枠（`PhotoSection`）のタップ = `takePhoto()`。写真枠の**下**に「ギャラリーから選ぶ」のテキストリンクを置き、`pickFromLibrary()` を呼ぶ
- 写真が未選択のときの枠内の文言は「タップして撮影」に変える（現状は「写真を追加」相当）

### S-4 / S-5: 最寄りスポットの既定選択

`useRecordForm` に既定選択を足す。**以下をすべて満たすときだけ**選択する:

| 条件                                                     | 理由                                                     |
| -------------------------------------------------------- | -------------------------------------------------------- |
| `route.params.spotId` が**無い**                         | 明示指定が最優先（ボトムシート経路の既存挙動を壊さない） |
| ユーザーが**まだスポットを選んでいない**                 | 一度選んだ後に上書きしない                               |
| `permissionStatus === Location.PermissionStatus.GRANTED` | `DEFAULT_LOCATION` フォールバックを踏まない              |
| 最寄りスポットの距離が **500m 以内**                     | 境内にいるときだけ効かせる                               |

**500m の根拠**: 記録は帰宅後に行われることもある。閾値が緩いと自宅近くの寺社が既定選択され、そのまま送信される事故になる。境内にいる場合に限定するため厳しくする。閾値は `src/constants/` に `AUTO_SELECT_SPOT_RADIUS_KM = 0.5` として定義し、直値を書かない。

**S-5 の表示**: 既定選択された場合、`SpotSelector` の選択済み行に「現在地から自動選択」のラベルを出す。ユーザーが自分でタップして選び直した場合はラベルを消す。

### S-6: `deleteStamp` の削除順

現状は**画像 → DB 行**の順（`stamps.ts:169-173`）。DB 行の削除が失敗すると、**画像だけ消えて stamp が残り、ギャラリーに画像の出ない御朱印が残る**。

取り消しは新しい呼び出し元であり、失敗時に「取り消せていないのに写真だけ消えた」状態になるのは避けたい。**DB 行 → 画像**の順に変える。この順なら失敗時に残るのは孤児画像だけで、ユーザーから見た表示は壊れない。

既存の呼び出し元（御朱印詳細の削除）にも同じ改善が及ぶ。
