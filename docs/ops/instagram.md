## 1. 投稿の仕組み（自動・毎日 19:07）

オーナーの Mac の launchd `com.goshuin.ig-daily`（`~/Library/LaunchAgents/com.goshuin.ig-daily.plist`）が、毎日 19:07 に次を動かす。Mac が眠っていて出せなかった日は、20:07〜23:07 に毎時やり直す（その日にもう出していれば何もしない。2026-10-29 から）。

```sh
/usr/bin/python3 ~/goshuin-work/ig-325/publish.py next
```

| ファイル（`~/goshuin-work/ig-325/`） | 中身                                                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `publish.py`                         | 投稿する道具。Instagram Graph API（v26.0）を使う                                                               |
| `posts.json`                         | 投稿の目録。`posts` の並び順に 1 日 1 本ずつ出る                                                               |
| `posted.json`                        | 出した記録（id → media_id・permalink・時刻）。同じ id は 2 回出せない                                          |
| `deferred.json`                      | 後回しにしたもの（id → until・理由・回数）                                                                     |
| `logs/daily.log`                     | 毎日の実行のログ。**出たかどうかは、まずここを見る**                                                           |
| `drafts/`                            | 投稿する画像                                                                                                   |
| `compose.py`・`compose_famous.py`    | 御朱印の写真から投稿の画像を作る（Pillow。pyenv の `python3` で動かす。`/usr/bin/python3` には Pillow が無い） |
| `posts.json.bak-20261015`            | 10/15 に順番を組み替える前の目録                                                                               |

`publish.py` の使い方:

```sh
python3 publish.py check        # 鍵・権限・ファイル・メンションを確かめる（何も出さない）
python3 publish.py dry <id>     # 投稿の直前まで通す（下書きの箱は作るが、公開しない）
python3 publish.py post <id>    # その 1 本を公開する
python3 publish.py next         # まだ出していない次の 1 本を公開する（定期実行が使う）
python3 publish.py status       # 出したものの一覧
```

動きの決まり:

- 同じ日に 2 本は出さない（24 時間に 1 本）
- 次の 1 本が `"ready": false` なら、その日は止まる（オーナーの承認待ちの印）
- 画像は、Mac から一時的に公開して（cloudflared の一時トンネル）Instagram に読ませ、終わったら閉じる
- 動画（リール）が公開のところで断られたら、`deferred.json` に 2 日後まで後回しにして、その日は次の 1 本を出す
- 鍵は `~/.config/goshuin/meta-publish-token` から読む。画面にもログにも出さない

`posts.json` の 1 件の形:

```json
{
  "id": "11-fushimi",
  "kind": "image",
  "files": ["~/goshuin-work/ig-325/drafts/K1-fushimi.jpg"],
  "check": "何で確かめたか（公式サイトのどのページか・確かめた日・判断したこと）",
  "caption": "本文（ハッシュタグまで）"
}
```

`ready` を付けないものは出してよいもの。`"ready": false` はオーナーの承認待ち。

### 本文の形

```
（1 行目）場所と寺社の名前。例: 京都・伏見の伏見稲荷大社。

（由緒・人気を 1 行）例: 全国に約3万社あるといわれる稲荷神社の総本宮。…
（今の時期の行事・見どころを 1 行・日付つき）例: 11月8日は火焚祭。…

いただいた御朱印は、写真を1枚撮るだけで記録できます。参拝した日と寺社が残り、地図にピンが立ちます。

※ 由緒と行事は〇〇の公式サイトの案内です。参拝の前に、公式の案内もご確認ください。

#寺社名 #地名 #〇〇御朱印 #行事名 #御朱印 #御朱印巡り #神社巡り
```

- 由緒と行事は**その寺社の公式サイトで確かめる**。年が書いていない行事は「例年」と書く
- 紅葉の見頃のように公式に無いものは「例年の目安」と書く
- 確かめたページと日付は、`check` に残す
- 日付のある行事を書いたら、投稿が出る日とずれないかを見る。出る日が行事より後になったら、その行を消す
- 寺社の公式サイトに、撮影や SNS への掲載を断る記述が無いかを見る。あったら出さずにオーナーに聞く。境内での撮影の注意は、御朱印の写真には当たらないと判断してきた（伏見稲荷大社・伊勢山皇大神宮）。判断は `check` に書く

### 画像の作り方

画像は、オーナーがアプリに記録した御朱印の写真から作る。

1. 本番の DB から、オーナーのアカウントのその寺社の記録の `image_path` を読む（読むだけ。`supabase db query --linked -f <sql>`。オーナーのアカウントの見分け方は PRIVATE.md）
2. 写真は R2 の変換 URL で **1 枚だけ** 取り寄せる。同じ写真を何度も読まない（Supabase の転送量の約束）。シミュレータは使わない
   `https://img.goshuinsanpo.com/cdn-cgi/image/width=1200,quality=90,format=jpeg/<image_path>`
3. 取り寄せた写真は `~/goshuin-work/ig-325/raw3/` に置く
4. `compose_famous.py` に 1 行足して、pyenv の `python3` で動かす。`goshuin_post('<画像の名前>', <元の写真>, <切り出す範囲>, '<寺社名>', '<県市・参拝の日>')` の形で、`drafts/<画像の名前>.jpg` ができる
5. 画像の日付は、御朱印に書かれた日付とアプリの記録が合うかを見る。食い違うときは月までにする（伏見稲荷大社はそうした）
6. 取り寄せた写真は、使う前に目で見る。同じ寺社の記録でも、写真が摂社・末社の御朱印のことがある（鹽竈神社の 2026-04-05 の記録は摂社の冠川神社だった）。取り寄せの途中で Mac がスリープすると、画像が途中で切れて下が網目になる（北野天満宮で起きた）
7. 縦に長い写真は、`goshuin_post` の最後に `pw=640` のように写真の幅を渡して小さくし、題字を画面に収める（八坂神社がそう。いつもは 760）
8. 横長の写真（見開きの御朱印）は `goshuin_post_wide` を使う。引数は `goshuin_post` と同じ形で、写真を広く、上下の真ん中に置く（例: `goshuin_post_wide('M1-shiogama', f'{RAW3}/shiogama2.jpg', (10, 30, 1190, 880), '志波彦神社・鹽竈神社', '宮城県塩竈市・令和8年の初詣')`）

## 6. 鍵の期限と作り直し

- 鍵は Meta の長期ユーザートークン（60 日）。置き場所は `~/.config/goshuin/meta-publish-token`。**期限は 2026-12-10 12:46**（10/17 に Graph API の debug_token で確かめた）
- **12 月の初めに、オーナーに作り直しを頼む。** オーナーが自分のターミナルで次を動かす。App Secret と、Graph API エクスプローラーで作った短期の鍵を貼ると、60 日の鍵に替えて保存する（画面には出ない）

  ```sh
  /usr/bin/python3 ~/goshuin-work/ig-325/save-token.py
  ```

- 作り直したら `publish.py check` で確かめる
