# 開発ハーネス

自律開発ループの状態管理ディレクトリ。フロー本体は `/build-feature` スキルを参照。

| ファイル            | 役割                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------- |
| `feature-list.json` | フェーズごとの機能リスト。`passes` は Evaluator PASS + 全テスト通過のときのみ true にできる |
| `progress.md`       | セッションをまたぐ引き継ぎメモ。機能完了ごとに1〜3行追記                                    |
| 契約書              | `docs/issues/issue-XXX-*.md`（既存の Issue 設計テンプレートをそのまま契約書として使う）     |

## 設計方針（2026-08 刷新）

- 最小ハーネスで始め、必要なときだけ複雑さを足す
- 生成と評価の分離: 実装はメインループ、検証は goshuin-evaluator（別コンテキスト・Sonnet）
- 人間ゲートは push/PR 直前の1箇所のみ
- 詳細な設計判断と出典は `docs/product/direction.md` の「開発フロー刷新の方針」を参照
